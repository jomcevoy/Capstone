### 19.1: Refining your strategies for the black-box optimisation challenge

#### Which prompt patterns (zero-shot, few-shot, etc.) did you use, and why? What changed when you simplified vs structured the prompt?
Throughout this process because Bayesian Optimisation is highly sensitive to kernel selection and hyperparameter tuning, structured prompts have been used to ensure the model outputs mathematically sound and numerically stable. The prompts were effectively few shot prompts based on the expanding set of inputs features and output results.

#### What temperature, top-p, top-k and max-tokens settings did you choose? How did they trade off coherence vs diversity? How did they affect your chosen query?
Bayesian Optimisation (BO) possesses direct functional equivalents to LLM decoding settings like temperature and Top-P. However, because BO is a mathematical search framework rather than a text-generation model, the trade-off is framed as Exploitation (Coherence) vs. Exploration (Diversity). 

Temperature, that controls the randomness and creativity in a LLM,  is analogous to the scalar factors (beta/kappa) in the acquisition function. As these increase the function explores more of the landscape.Top-p/top-k have  similar equivalents in BO, where decoding can be limited through trust regions (TuRBO), through probability thresholds, or through the tuning of length scales. In early queries the temperatures were raised and in later queries it has been lowered and the search space has been reduced.

#### Did token boundaries or unusual input strings affect the model’s behaviour? When did you notice token count limits or truncation influencing the outputs? If no such cases were observed, explain how you checked for those cases.
Token boundaries and unusual input strings (like "glitch tokens") in LLMs behave almost exactly like the chaotic, non-differentiable boundaries found in n-dimensional black-box optimisation. In both cases, you are dealing with a hidden landscape where moving just a fraction (or changing a single character) can cause the system to fall off a metaphorical cliff, completely altering its output. This is evident in the hyper-parameter function, because the system is dynamic and full of local optima.

With 17 data points, what limitations did you encounter, such as prompt overfitting, attention focusing on irrelevant context or diminishing returns from longer inputs?

Just like a prompt overfits to the quirks of a specific dataset batch, the GP overfits to the quirks of individual, noisy evaluation points. Similarly In LLMs, the model's attention mechanism gets distracted by irrelevant background text. In GP-BO, this is equivalent to being distracted by uninformative or irrelevant input dimensions in the search space. Running correlation, mutual information and total importance analysis on the function data sets helps identify the least important dimensions.

#### Which strategies did you try to reduce hallucinations? For example, did you use tighter instructions, retrieval of prior relevant information or constrain the output format?
Standard acquisition functions like classic Expected Improvement (EI) or Upper Confidence Bound (UCB) are easily fooled by highly volatile noisy peaks. To help reduce the impact of these we reduce the search space through lengthscales or TuRBO. Ideally evaluating the objective function across a diverse, mini-batch sample at every step would average out the hallucinations of a single run.
 
#### In future rounds, how would you scale your prompting and decoding strategies when working with larger data sets or more complex LLMs?
As the data size (N) and dimensionality (D) of the BO-GP grows, the interface between the LLM and the optimiser should transition from a simple text input  to a structured pipeline. Also moving to batch / parallel optimisation would help with additional computation loads. And finally moving modelling to PyTorch which can handle the mathematical bottlenecks of scale as well as utilise gradient based optimisers bypassing the curse of dimensionality. 

#### How did these design choices for prompts and decoding help you think like a practitioner balancing exploration, risk and computational constraints in a black-box setting with incomplete information?
Operating within this black-box framework with incomplete information forces a practitioner to think like a risk manager balancing a tight computational budget. The focus of hyper-parameter selection (driving Exploration or Exploitation) is a dynamic trade-off. Tuning decoding parameters (like Temperature or top-p) acts as a physical knob for risk; higher values force the model to explore wide, uncertain regions, while lower values exploit known safe zones. As a practitioner we now understand that the surrogate model should be designed  to expect noise, hallucinations and irrelevant features that need to be accounted for and adapted for.
