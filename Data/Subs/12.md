
### 12.1: Applying machine learning techniques to black-box functions
#### What was the main principle or heuristic you used to decide on each query point (e.g. exploitation of high outputs, exploration of uncertain regions, diversity of samples)? How do you plan to adjust your strategy in future rounds based on the current performance or uncertainty levels?
To help optimise the unknown objective functions I first ran a series of statistical tests on the initial data to help with feature filtering. Following the filtering I could then apply an acquisition function to determine the next query point. 

Function 1 - 2D Array (Radiation) - Here the data identifies one radiation peak with a highly restricted radius of proximity. To aid exploration here I am experimenting with a high variance acquisition function, with beta set to 10, and a Matern kernal. In future rounds continue with exploration but with the last 5 queries shift to exploitation reducing the beta and the length scale of the kernel. It would be good to know how many radiation peaks there were to help decide when to shift focus.

Function 2 - 2D Array (Log Likelihood) - Here the visualised data shows a jagged peak in one corner of the search space but with other potential peaks. Again focusing on areas of high variance utilises an Upper Confidence Bound acquisition function and RBF kernel to explore the search space. Again in future rounds continue with exploration but with the last 5 queries shift to exploitation reducing the beta and the length scale of the kernel or even shifting to Expected Improvement  acquisition mode once we have focused on a local peak.

Function 3 - 3D Array (Drug Test)- Initial filtering identified one feature to represent 80% of the total importance. In the initial rounds of queries will use a standard exploration function to map out the search space and to continue to validate the 80% feature importance. In future rounds if the feature importance holds I will shift the exploration function to focusing only on that feature before shifting to an exploitation to focus on the true minimum.

Function 4 - 4D Array (Dynamic)- Having computed mutual information scores and total importance scores for the inputs, All four inputs are important and therefore need careful consideration, the system is dynamic and full of local optima. Again in the initial rounds of queries will use a standard exploration function UCB with RBF kernel to map out the search space and to continue to validate the feature importance. In future rounds will reduce the beta and focus on a exploiting a local maxima,  It would be good to know if dynamic means past query points may change in value over time, or the surface itself might drift.

Function 5 - 4D Array (Chemical) - The importance analysis identified only one feature with independent strong correlation but that another feature has a higher overall importance - indicating complex non-linear interactions. In initial rounds use a high-exploration UCB strategy with the RBF kernel to get a rough topological map and confirm these feature importance. In later rounds droop the beta pulling query points away from the boundaries and into the high-performing regions. Then switch the acquisition function entirely from UCB to Expected Improvement (EI) with a low exploration parameter. The true optimal yield might lie right on the edge of safe operating limits - are there any actual dangerous limits

Function 6 - 5D Array (Cake) - The importance analysis identified two features that were more important but initially would utilise the standard Expected Improvement (EI) with a high exploration parameter to explore this landscape. Reducing the parameter in later queries and ultimately focusing on the two features of importance. 

Function 7 - 6D Array (ML Hyper-Tune) - The importance analysis identified two features that had little impact on the scenario. Again I would utilise the standard Expected Improvement (EI) with a high exploration parameter to explore this landscape. Reduce the parameter in later queries and look to length scale the kernel, with large scales for those parameters with little influence. 

Function 8 - 8D Array (Black Box) - Starting with 40 samples may not be enough given the search space of 8 features. Hopefully we are given some further techniques to reduce the scales involved. For the initial query I have utilised the standard Expected Improvement (EI) with a high exploration parameter (from Carleton) but because the function is high-dimensional and likely complex, a global optimisation is likely hard to find, so identifying strong local maxima would be a practical strategy.

#### Which function(s) were most challenging to query, and why?
Function 1 - Needle in a haystack - radiation peaks with a highly restricted radius of proximity. No slope for the acquisition function to work on.

Function 4 - Dynamic - little scope to reduce dimensions and concerns over the meaning of a dynamic system.

Function 8 - Black Box - The Curse of Dimensionality: In an 8-dimensional space, the volume of the search space grows exponentially - challenging due to the sheer volume of empty space.
